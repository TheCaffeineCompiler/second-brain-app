# Product Requirements Document: LLM-Powered Second Brain App

## 1. Core Architecture & Storage
* **Markdown-First Foundation:** All raw notes and enriched data must be stored in standard Open Knowledge Format (OKF) to ensure portability and accessibility.
* **Headless Syncing:** The system must support background syncing (e.g., via CLI tools like Obsidian's headless CLI or Git) to move files between local storage and cloud sandboxes without manual push/pull commands.
* **Open Environment:** Files should be easily accessible to external local or cloud-based AI agents and CLI tools.

## 2. Input & Capture Mechanisms
* **Frictionless Voice Dictation:** 
  * Integrated voice-to-text functionality optimized for speed (~200 words per minute).
  * Support for local AI transcription models (e.g., Whisper) to maintain privacy and reduce subscription costs.
  * System-wide hotkey support (e.g., holding `Option` or `Fn`) for instant capture on desktop.
  * Companion mobile app for capturing thoughts on the go.
* **Raw Data Tolerance:** The input interface must be designed to accept "brain dumps" (unformatted, rambling, or unstructured text) without requiring the user to manually format, bullet-point, or categorize the data at the time of entry.

## 3. AI Agent Enrichment (The "Processing" Layer)
* **Automated Tagging & Categorization:**
  * AI agents automatically review raw notes and assign relevant tags.
  * **Tag Constriction:** Agents must reference a pre-existing "reference folder" of tags to prevent tag sprawl and AI hallucination, only creating new tags when a strong, recurring pattern emerges.
* **Source Resolution:** Agents must have web search capabilities (e.g., Exa or standard web tools) to find and append URLs for podcasts, articles, or books mentioned casually in the raw notes.
* **Metadata Injection:** Automatically append enrichment timestamps to notes to track which files have been processed and which require a new pass.
* **Automated Backlinking:** The system must analyze new notes, perform keyword/semantic searches against the existing database, and automatically inject links to related past notes at the bottom of the document.

## 4. Synthesis & Knowledge Generation
* **Auto-Generated Wikis:** 
  * The app must be able to digest a specific folder or focus area and programmatically generate a structured Wiki.
  * **Entity Extraction:** Automatically group references by entities such as *People*, *Organizations*, *Concepts*, and *Sources*.
  * Useful for personal research (e.g., tracking characters in a book) or professional use (e.g., tracking client meetings and project details).

## 5. Automation & Background Scheduling
* **"Overnight" Cloud Processing:** 
  * Integration with cloud automation runners (like oz.dev or automated cron jobs) to process notes in the background.
  * The user should be able to dump raw notes all day, and the system automatically syncs, runs the enrichment agents, generates wikis, and pushes the organized data back overnight.

## 6. Visualization & Interface
* **Dynamic HTML/Tailwind Views:** The interface should natively render HTML generated by LLMs to create custom, interactive views of the data.
* **Interactive Graph View:** A visual map of nodes representing how concepts, tags, and notes are interconnected, allowing users to spot gaps in their thinking or explore "rabbit holes."
* **Habit/Activity Tracking:** Visual charts (e.g., GitHub-style contribution graphs or burndown charts) to track the user's note-taking consistency and focus areas over time.

## 7. Technology & Architecture
* **12 Factor App**: Make sure to follow these principles to make the app flexible.
* **Hexagonal Architecture**: The architecture should follow the ports-and-adapters-approach.
* **GCP-first**: For now, we want to deploy the app using Google Cloud Run
* **Components**: Serve the app as a progressive WebApp, following the Backend-for-frontend (BFF) pattern.
