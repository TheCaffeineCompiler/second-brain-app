# No LLM-generated HTML views

§6 asks the interface to natively render HTML generated by an LLM, to give custom interactive
views of the data. This is dropped for now.

The decisive objection is specific to this system rather than general caution about generated
markup. **The pipeline's inputs are untrusted.** Captures cite external Sources, and enrichment
reads material from the open web — article text, episode descriptions, page metadata. If that
content can influence LLM-generated HTML which is then rendered in the app, there is a direct
path from a hostile web page to script execution inside a PWA that holds the user's entire
knowledge base and a Git write credential. Defending that properly means sanitisation and a
content security policy strict enough to remove most of the interactivity that motivated the
feature.

The gain is small in return. A well-built static reading view covers what the requirement was
reaching for, and the genuinely dynamic surfaces — the graph and the review queues — are worth
building as real components rather than as generated markup.

## Consequences

Should this be revisited, the safe form is a **closed set of parameterised components the model
may select and populate**, never free-form markup — the same closed-vocabulary discipline
ADR-0006 applies to Tags.
